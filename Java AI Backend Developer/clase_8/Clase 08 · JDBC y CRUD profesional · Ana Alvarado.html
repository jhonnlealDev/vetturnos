01FUNDAMENTO

🌉 El puente entre Java y MySQL

Punto de partida

Si la tienda ya almacena clientes en MySQL, ¿cómo puede un vendedor registrarlos desde una aplicación Java sin abrir Workbench?

Hasta ahora, las instrucciones INSERT, SELECT, UPDATE y DELETE se ejecutaban manualmente. En una aplicación real, el usuario interactúa con menús, formularios o botones; el programa debe encargarse de hablar con la base de datos.

Cómo imaginarlo

Java y MySQL son dos sistemas distintos. JDBC define un enchufe estándar y el driver de MySQL funciona como el cable que traduce las solicitudes para ese motor específico.

Definición técnica

JDBC es la API estándar de Java para establecer conexiones, ejecutar sentencias SQL y procesar resultados de bases de datos relacionales.

En palabras sencillas

Es el conjunto de reglas que permite que tu código Java envíe órdenes a una base de datos y reciba sus respuestas.

Ejemplo real

El vendedor registra a Laura en la aplicación. Java recibe los datos, JDBC los envía a MySQL y la información queda guardada incluso después de cerrar el programa.

Caso de negocio

Tienda con datos persistentes

La base tienda ya contiene las tablas cliente y pedido. El objetivo ahora es conectar el sistema Java con esa información y administrar clientes mediante las cuatro operaciones CRUD.

Comprueba la idea

¿JDBC y el driver de MySQL son la misma cosa?
No. JDBC viene con Java y define las reglas generales. MySQL Connector/J es la implementación específica que traduce esas reglas para MySQL.
02CONFIGURACIÓN

📦 Driver y classpath

Para que JDBC pueda comunicarse con MySQL, el proyecto necesita la librería oficial MySQL Connector/J. Se distribuye como un archivo .jar: un paquete de clases Java ya compiladas.

Archivo JAR

Un Java Archive empaqueta clases y recursos reutilizables en un solo archivo.

Classpath

Es la lista de ubicaciones donde Java busca las clases necesarias para compilar y ejecutar.

Relación entre ambos

Guardar el JAR no basta: debes agregarlo al classpath para que Java pueda encontrar y cargar el driver.

Preparar el proyecto

Descarga y registra MySQL Connector/J

  1. 01

    Descarga MySQL Connector/J desde dev.mysql.com/downloads/connector/j/ y elige la distribución Platform Independent.

  2. 02

    Descomprime el archivo y copia mysql-connector-j-9.x.x.jar dentro de una carpeta nueva llamada lib.

  3. 03

    En IntelliJ, usa Add as Library. En VS Code, agrégalo desde Java Projects → Referenced Libraries.

Qué vamos a hacer

Verificar la estructura mínima antes de escribir Java.

Por qué lo hacemos

La ubicación del driver y su registro en el classpath deben quedar claros antes de intentar una conexión.

Qué aprenderás

A distinguir entre tener una librería guardada y tenerla disponible para el proyecto.

03CONEXIÓN

🔌 Primera conexión

Una conexión necesita cuatro datos: protocolo y motor, host y puerto, nombre de la base, y credenciales. Para este proyecto la URL será jdbc:mysql://localhost:3306/tienda.

Anatomía de la URL

jdbc:mysql identifica el protocolo y el motor; localhost señala tu computador; 3306 es el puerto habitual de MySQL; tienda es la base que se abrirá.

Qué vamos a hacer

Crear una clase exclusiva para abrir conexiones.

Por qué lo hacemos

Centralizar la configuración evita repetir URL, usuario y contraseña en cada operación.

Qué aprenderás

A usar DriverManager, devolver un objeto Connection y reconocer que la conexión puede lanzar SQLException.

CREARsrc/config/ConexionBD.java
package config;

import java.sql.Connection;
import java.sql.DriverManager;
import java.sql.SQLException;

public final class ConexionBD {

    private static final String URL = "jdbc:mysql://localhost:3306/tienda";
    private static final String USUARIO = "root";
    private static final String CLAVE = "admin";

    private ConexionBD() {
    }

    public static Connection obtenerConexion() throws SQLException {
        return DriverManager.getConnection(URL, USUARIO, CLAVE);
    }
}

Credenciales locales

Qué ocurre: copiar root/admin puede producir acceso denegado.

Cómo leerlo: el mensaje contiene Access denied for user.

Cómo resolverlo: usa el usuario y la contraseña configurados en tu instalación de MySQL.

Qué vamos a hacer

Abrir y cerrar una conexión de prueba.

Por qué lo hacemos

Es mejor confirmar la infraestructura antes de añadir el CRUD.

Qué aprenderás

A usar try-with-resources para cerrar recursos automáticamente.

04DISEÑO

🗂️ Modelo y patrón DAO

Decisión de diseño

¿Qué pasaría si el SQL de clientes quedara mezclado con menús, validaciones y mensajes de consola?

El código tendría varias responsabilidades y cambiar la persistencia obligaría a revisar toda la aplicación. El patrón DAO concentra el acceso a datos de una entidad en un componente dedicado.

Definición técnica

Data Access Object separa la lógica de persistencia de la lógica que usa los datos.

En palabras sencillas

El resto del programa pide insertar, listar, actualizar o eliminar; el DAO decide qué SQL ejecutar.

Ejemplo real

Es como un cajero: tú solicitas una operación, pero solo él conoce el procedimiento para acceder a la bóveda.

Qué vamos a hacer

Crear el modelo Java que representa una fila de la tabla cliente.

Por qué lo hacemos

JDBC entrega valores por columnas; la aplicación necesita convertirlos en objetos de dominio.

Qué aprenderás

A diferenciar un cliente nuevo, sin id, de un cliente recuperado de la base, con id.

CREARsrc/model/Cliente.java
package model;

public class Cliente {
    private int id;
    private String nombre;
    private String email;
    private String ciudad;

    public Cliente(int id, String nombre, String email, String ciudad) {
        this.id = id;
        this.nombre = nombre;
        this.email = email;
        this.ciudad = ciudad;
    }

    public Cliente(String nombre, String email, String ciudad) {
        this.nombre = nombre;
        this.email = email;
        this.ciudad = ciudad;
    }

    public int getId() { return id; }
    public String getNombre() { return nombre; }
    public String getEmail() { return email; }
    public String getCiudad() { return ciudad; }

    @Override
    public String toString() {
        return "Cliente{id=" + id + ", nombre='" + nombre
                + "', email='" + email + "', ciudad='" + ciudad + "'}";
    }
}

Qué vamos a hacer

Definir el contrato de acceso a datos para clientes.

Por qué lo hacemos

La interfaz separa las operaciones disponibles de su implementación JDBC.

Qué aprenderás

A expresar el CRUD como un contrato estable que otra clase deberá cumplir.

Responsabilidad única

05CREATE Y SEGURIDAD

➕ Insertar sin abrir una vulnerabilidad

Concatenar datos del usuario dentro del SQL permite que una entrada altere la consulta. Ese problema se conoce como inyección SQL.

Qué vamos a observar

Una forma insegura de construir SQL.

Por qué lo hacemos

Reconocer el error permite entender por qué PreparedStatement es obligatorio.

Qué aprenderás

A identificar concatenación de datos externos como una vulnerabilidad, no como una simple decisión de estilo.

EJECUTAREjemplo inseguro
String sql = "INSERT INTO cliente (nombre, email, ciudad) VALUES ('"
        + cliente.getNombre() + "', '"
        + cliente.getEmail() + "', '"
        + cliente.getCiudad() + "')";

Inyección SQL

Qué ocurre: una entrada como x' OR '1'='1 puede convertirse en parte de la instrucción y hacer verdadera una condición para todas las filas.

Cómo leerlo: los datos y el código SQL quedaron mezclados en una misma cadena.

Cómo resolverlo: usa parámetros ? y asigna cada valor mediante métodos como setString o setInt.

PreparedStatement

La estructura SQL se prepara primero y los valores se incorporan después como datos. Un texto malicioso permanece como texto y no puede reescribir la sentencia.

Qué vamos a hacer

Crear la implementación del DAO y programar la operación de inserción.

Por qué lo hacemos

El SQL debe vivir en la capa de acceso a datos y utilizar parámetros seguros.

Qué aprenderás

A preparar una sentencia, completar parámetros desde la posición 1 y ejecutar una modificación con executeUpdate.

CREARsrc/dao/ClienteDAOImpl.java
package dao;

import config.ConexionBD;
import java.sql.Connection;
import java.sql.PreparedStatement;
import java.sql.SQLException;
import java.util.List;
import model.Cliente;

public class ClienteDAOImpl implements ClienteDAO {

    @Override
    public void insertar(Cliente cliente) {
        String sql = "INSERT INTO cliente (nombre, email, ciudad) VALUES (?, ?, ?)";

        try (Connection con = ConexionBD.obtenerConexion();
             PreparedStatement ps = con.prepareStatement(sql)) {

            ps.setString(1, cliente.getNombre());
            ps.setString(2, cliente.getEmail());
            ps.setString(3, cliente.getCiudad());

            int filas = ps.executeUpdate();
            System.out.println("Filas insertadas: " + filas);
        } catch (SQLException e) {
            System.out.println("Error al insertar: " + e.getMessage());
        }
    }

    @Override
    public List<Cliente> listar() {
        throw new UnsupportedOperationException("Pendiente de implementar");
    }

    @Override
    public void actualizar(Cliente cliente) {
        throw new UnsupportedOperationException("Pendiente de implementar");
    }

    @Override
    public void eliminar(int id) {
        throw new UnsupportedOperationException("Pendiente de implementar");
    }
}
06READ

🔍 Convertir filas en objetos

Definición técnica

ResultSet representa las filas devueltas por una consulta SELECT.

En palabras sencillas

Es una tabla temporal que Java recorre una fila a la vez con next().

Transformación

Cada fila se lee por nombre de columna y se convierte en un objeto Cliente que se agrega a una lista.

Qué vamos a hacer

Reemplazar el método temporal listar por una consulta real.

Por qué lo hacemos

El resto del programa debe recibir objetos Java y no conocer detalles de JDBC.

Qué aprenderás

A diferenciar executeQuery de executeUpdate y a mapear columnas hacia objetos.

REEMPLAZARsrc/dao/ClienteDAOImpl.java · método listar
@Override
public List<Cliente> listar() {
    List<Cliente> clientes = new ArrayList<>();
    String sql = "SELECT id, nombre, email, ciudad FROM cliente";

    try (Connection con = ConexionBD.obtenerConexion();
         PreparedStatement ps = con.prepareStatement(sql);
         ResultSet rs = ps.executeQuery()) {

        while (rs.next()) {
            Cliente cliente = new Cliente(
                    rs.getInt("id"),
                    rs.getString("nombre"),
                    rs.getString("email"),
                    rs.getString("ciudad")
            );
            clientes.add(cliente);
        }
    } catch (SQLException e) {
        System.out.println("Error al listar: " + e.getMessage());
    }

    return clientes;
}

Importaciones necesarias

Agrega java.sql.ResultSet y java.util.ArrayList en la implementación. El IDE puede incorporarlas automáticamente.

Comprueba la diferencia

¿Por qué un SELECT usa executeQuery y no executeUpdate?
executeQuery devuelve un ResultSet con filas. executeUpdate se usa cuando una sentencia modifica datos y devuelve la cantidad de filas afectadas.
07UPDATE Y DELETE

✏️ Modificar datos con precisión

Regla crítica

¿Qué filas modificaría un UPDATE o DELETE que no incluyera una condición WHERE?

Sin WHERE, la operación afecta todas las filas. El identificador permite apuntar a un registro concreto, y el número devuelto por executeUpdate confirma cuántas filas cambiaron.

Qué vamos a hacer

Implementar la actualización de un cliente identificado por su id.

Por qué lo hacemos

Los datos cambian y la operación debe limitarse a la fila correcta.

Qué aprenderás

A respetar el orden de los parámetros y ubicar el id en la condición WHERE id = ?.

REEMPLAZARsrc/dao/ClienteDAOImpl.java · método actualizar
@Override
public void actualizar(Cliente cliente) {
    String sql = "UPDATE cliente SET nombre = ?, email = ?, ciudad = ? WHERE id = ?";

    try (Connection con = ConexionBD.obtenerConexion();
         PreparedStatement ps = con.prepareStatement(sql)) {

        ps.setString(1, cliente.getNombre());
        ps.setString(2, cliente.getEmail());
        ps.setString(3, cliente.getCiudad());
        ps.setInt(4, cliente.getId());

        int filas = ps.executeUpdate();
        System.out.println("Filas actualizadas: " + filas);
    } catch (SQLException e) {
        System.out.println("Error al actualizar: " + e.getMessage());
    }
}

Qué vamos a hacer

Implementar la eliminación de un cliente por id.

Por qué lo hacemos

La eliminación necesita una condición inequívoca para no afectar toda la tabla.

Qué aprenderás

A ejecutar un DELETE parametrizado y verificar si la fila existía.

REEMPLAZARsrc/dao/ClienteDAOImpl.java · método eliminar
@Override
public void eliminar(int id) {
    String sql = "DELETE FROM cliente WHERE id = ?";

    try (Connection con = ConexionBD.obtenerConexion();
         PreparedStatement ps = con.prepareStatement(sql)) {

        ps.setInt(1, id);
        int filas = ps.executeUpdate();
        System.out.println("Filas eliminadas: " + filas);
    } catch (SQLException e) {
        System.out.println("Error al eliminar: " + e.getMessage());
    }
}

Operaciones destructivas

Antes de ejecutar: revisa siempre que UPDATE y DELETE incluyan la condición correcta. En producción, una sentencia sin filtro puede causar pérdida masiva de datos.

08DIAGNÓSTICO

🛡️ Leer errores SQL

La base de datos es un recurso externo: puede estar apagada, rechazar credenciales o proteger restricciones. Por eso JDBC usa SQLException, una excepción que debes manejar o declarar.

Mapa de diagnóstico

Busca la frase que revela la causa

  1. 01

    No suitable driver found: el driver no está disponible en el classpath.

  2. 02

    Access denied for user: el usuario o la contraseña no coinciden.

  3. 03

    Unknown database: la base indicada en la URL no existe o está mal escrita.

  4. 04

    Duplicate entry: el valor viola una restricción UNIQUE, como un correo repetido.

  5. 05

    Foreign key constraint fails: se intenta relacionar una fila con un registro padre inexistente.

La base también protege el sistema

Las restricciones modeladas en MySQL siguen funcionando cuando el acceso ocurre desde Java. UNIQUE evita duplicados y una llave foránea evita datos huérfanos, incluso cuando el código comete un error.

Cómo depurar

No memorices mensajes completos. Identifica la frase principal, ubica la capa que falló —driver, conexión, esquema o datos— y corrige una causa a la vez.

10INTEGRACIÓN

🚀 Ejecutar el CRUD completo

El cierre consiste en integrar las cuatro operaciones. El main trabaja con la interfaz ClienteDAO, crea objetos y coordina el flujo. No conoce consultas SQL ni detalles de conexión.

Qué vamos a hacer

Consolidar la implementación final del DAO con las cuatro operaciones.

Por qué lo hacemos

El archivo debe quedar funcional, sin métodos temporales ni fragmentos pendientes.

Qué aprenderás

A reconocer el patrón repetido: conexión, sentencia preparada, parámetros, ejecución, cierre y manejo del error.

REEMPLAZARsrc/dao/ClienteDAOImpl.java
package dao;

import config.ConexionBD;
import java.sql.Connection;
import java.sql.PreparedStatement;
import java.sql.ResultSet;
import java.sql.SQLException;
import java.util.ArrayList;
import java.util.List;
import model.Cliente;

public class ClienteDAOImpl implements ClienteDAO {

    @Override
    public void insertar(Cliente cliente) {
        String sql = "INSERT INTO cliente (nombre, email, ciudad) VALUES (?, ?, ?)";
        try (Connection con = ConexionBD.obtenerConexion();
             PreparedStatement ps = con.prepareStatement(sql)) {
            ps.setString(1, cliente.getNombre());
            ps.setString(2, cliente.getEmail());
            ps.setString(3, cliente.getCiudad());
            System.out.println("Filas insertadas: " + ps.executeUpdate());
        } catch (SQLException e) {
            System.out.println("Error al insertar: " + e.getMessage());
        }
    }

    @Override
    public List<Cliente> listar() {
        List<Cliente> clientes = new ArrayList<>();
        String sql = "SELECT id, nombre, email, ciudad FROM cliente";
        try (Connection con = ConexionBD.obtenerConexion();
             PreparedStatement ps = con.prepareStatement(sql);
             ResultSet rs = ps.executeQuery()) {
            while (rs.next()) {
                clientes.add(new Cliente(
                        rs.getInt("id"),
                        rs.getString("nombre"),
                        rs.getString("email"),
                        rs.getString("ciudad")
                ));
            }
        } catch (SQLException e) {
            System.out.println("Error al listar: " + e.getMessage());
        }
        return clientes;
    }

    @Override
    public void actualizar(Cliente cliente) {
        String sql = "UPDATE cliente SET nombre = ?, email = ?, ciudad = ? WHERE id = ?";
        try (Connection con = ConexionBD.obtenerConexion();
             PreparedStatement ps = con.prepareStatement(sql)) {
            ps.setString(1, cliente.getNombre());
            ps.setString(2, cliente.getEmail());
            ps.setString(3, cliente.getCiudad());
            ps.setInt(4, cliente.getId());
            System.out.println("Filas actualizadas: " + ps.executeUpdate());
        } catch (SQLException e) {
            System.out.println("Error al actualizar: " + e.getMessage());
        }
    }

    @Override
    public void eliminar(int id) {
        String sql = "DELETE FROM cliente WHERE id = ?";
        try (Connection con = ConexionBD.obtenerConexion();
             PreparedStatement ps = con.prepareStatement(sql)) {
            ps.setInt(1, id);
            System.out.println("Filas eliminadas: " + ps.executeUpdate());
        } catch (SQLException e) {
            System.out.println("Error al eliminar: " + e.getMessage());
        }
    }
}

Qué vamos a hacer

Reemplazar la prueba de conexión por el flujo completo de negocio.

Por qué lo hacemos

Necesitamos comprobar que cada operación persiste cambios reales y que el DAO oculta los detalles de JDBC.

Qué aprenderás

A orquestar el CRUD desde la aplicación usando objetos y una abstracción de acceso a datos.

REEMPLAZARsrc/app/App.java
package app;

import dao.ClienteDAO;
import dao.ClienteDAOImpl;
import model.Cliente;

public class App {
    public static void main(String[] args) {
        ClienteDAO clienteDAO = new ClienteDAOImpl();

        System.out.println("=== INSERTAR ===");
        clienteDAO.insertar(new Cliente("Laura Gomez", "laura@mail.com", "Bogota"));
        clienteDAO.insertar(new Cliente("Pedro Diaz", "pedro@mail.com", "Medellin"));

        System.out.println("\n=== LISTAR ===");
        clienteDAO.listar().forEach(System.out::println);

        System.out.println("\n=== ACTUALIZAR ===");
        clienteDAO.actualizar(
                new Cliente(1, "Laura Gomez Ruiz", "laura.ruiz@mail.com", "Cali")
        );

        System.out.println("\n=== LISTAR TRAS ACTUALIZAR ===");
        clienteDAO.listar().forEach(System.out::println);

        System.out.println("\n=== ELIMINAR ===");
        clienteDAO.eliminar(2);

        System.out.println("\n=== LISTAR FINAL ===");
        clienteDAO.listar().forEach(System.out::println);
    }
}

Ejecuciones repetidas

Cómo leerlo: aparecerá Duplicate entry.

Cómo resolverlo: limpia los registros de prueba, cambia los correos o comenta temporalmente las inserciones después de verificarlas.
