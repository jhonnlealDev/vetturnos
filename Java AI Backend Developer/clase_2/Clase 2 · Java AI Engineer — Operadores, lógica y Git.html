01Control de versiones

🐙Git y GitHub desde cero

Antes de programar más, montamos el lugar donde vivirá tu código y su historia. Git lleva el registro en tu computador; GitHub lo guarda en internet.

Técnico

Git

Sistema de control de versiones distribuido (creado en 2005). Vive en tu computador y guarda la historia de cada cambio en tu código.

En la vida real

GitHub

La página web donde subes esa historia para guardarla en la nube y compartirla. Git ≠ GitHub: uno es la herramienta local, el otro es la nube.

📚
El nombre de archivos como tarea_final, tarea_final_2, tarea_final_ESTA_SÍ es control de versiones hecho a mano… y mal. Git lo hace bien y automático.
?
¿Cuál es la diferencia entre Git y GitHub?
RespuestaGit es la herramienta de control de versiones que corre localmente en tu computador y registra el historial de cambios. GitHub es la plataforma web que aloja repositorios Git en internet para guardarlos y compartirlos. Trabajan juntos, pero no son lo mismo.
Verificar que Git esté instalado

En la terminal de VS Code (la abres con Ctrl + ñ o View > Terminal):

Terminal 
git --version

Si responde algo como git version 2.x.x, ya está instalado. Si dice "command not found", hay que instalarlo desde git-scm.com/downloads.

⚠️
En Windows: tras instalar Git, cierra y vuelve a abrir VS Code (o la terminal) para que reconozca el comando. Si no, parecerá que "no se instaló".
Configurar tu identidad (una sola vez)

Git necesita saber quién hace cada cambio. Esto se configura una vez por computador. Usa el mismo correo con el que crearás tu cuenta de GitHub, para que tus commits queden conectados a tu perfil.

?
¿Qué hace cada uno de estos comandos?
Respuestagit status muestra qué archivos cambiaron y cuáles están listos para guardar. git add mueve esos cambios al área de staging (los prepara). git commit -m registra una versión en el historial local con un mensaje que describe qué hiciste. git push envía esos commits al repositorio remoto en GitHub.

02Valores que no cambian

🔒Constantes con final

Algunos valores no deberían cambiar nunca durante el programa. Para eso existen las constantes: se declaran una vez, se nombran, y quedan protegidas.

?
Si el IVA (19%) está escrito a mano como 0.19 en 30 lugares de tu programa y mañana cambia la ley, ¿qué problema tienes?
RespuestaTendrías que buscar y cambiar el valor en los 30 lugares, y seguramente olvidarías alguno — eso introduce un bug. La solución es declarar el valor una sola vez como constante: si cambia, lo modificas en un único punto.
Técnico

Constante con final

Una variable declarada final solo puede asignarse una vez. Cualquier intento posterior de reasignarla es un error de compilación.

En la vida real

El IVA de Colombia

El 19% se usa en muchos cálculos. Lo declaras una vez como final double IVA = 0.19; y todo el programa lo usa desde ahí.

Antes del código, lo que hace: declaramos dos constantes y las mostramos. El valor queda fijo y protegido.

Constantes.java 
public class Constantes {
    public static void main(String[] args) {
        final double IVA = 0.19;
        final int DIAS_SEMANA = 7;

        System.out.println("El IVA es: " + IVA);
        System.out.println("Días en una semana: " + DIAS_SEMANA);
    }
}
?
Si después de declarar una constante intentas reasignarla (por ejemplo IVA = 0.16), ¿compila el programa?
RespuestaNo compila. Java lo impide con el error que indica que no se puede asignar un valor a una variable final. Esto es deseable: final protege el valor y previene errores, porque el programa se niega a dejarte cambiarlo por accidente.
💡
Convención profesional: las constantes se escriben en MAYÚSCULAS_CON_GUION_BAJO (IVA, DIAS_SEMANA, PRECIO_BASE). Las variables normales van en camelCase (precioTotal, nombreCliente).
📚
Dato: Java tiene 8 tipos primitivos: byte, short, int, long, float, double, boolean, char. String no es primitivo — es una clase (java.lang.String).
03Hacer cálculos

🧮Operadores aritméticos

Los operadores de toda la vida… más uno que sorprende. Aquí empieza nuestro ejemplo que crece toda la clase: la calculadora del restaurante.

+
suma
−
resta
*
multiplicación
/

%

Antes del código: calculamos una propina del 10% sobre la cuenta y la sumamos al total. Esta es la base que haremos crecer.

Restaurante.java 
public class Restaurante {
    public static void main(String[] args) {
        double cuenta = 80000;
        double propina = cuenta * 0.10;
        double total = cuenta + propina;

        System.out.println("Cuenta:  " + cuenta);
        System.out.println("Propina: " + propina);
        System.out.println("Total:   " + total);
    }
}
El truco de la división entera
?
¿Cuánto da 7 / 2 en Java, si ambos son enteros?
RespuestaDa 3, no 3.5. Cuando divides dos enteros, el resultado es entero: Java descarta los decimales (los corta, no redondea). Para obtener 3.5, al menos uno de los dos números debe ser decimal (double).

Antes del código: mostramos cómo forzar el resultado decimal — basta con que uno de los operandos sea double.

Restaurante.java 
int a = 7;
int b = 2;
System.out.println(a / b);        // 3   (división entera: corta decimales)

double c = 7.0 / 2;               // 3.5 (uno es decimal)
System.out.println(c);
System.out.println(7.0 / 2);      // 3.5
System.out.println((double) 7 / 2); // 3.5
📚
Dato: la división / entre dos enteros realiza división entera (trunca hacia cero). Si al menos un operando es de punto flotante, la división es decimal.
El módulo % : el residuo, y para qué sirve
Restaurante.java 
System.out.println(10 % 3); // 1
System.out.println(10 % 2); // 0
System.out.println(9 % 2);  // 1
?
Si numero % 2 da 0, ¿qué sabes del número?
RespuestaQue es par. El módulo es la forma profesional de saber si un número es par, impar o múltiplo de algo: si el residuo de dividir entre 2 es 0, no sobró nada, así que es divisible por 2.
Incremento y decremento
Restaurante.java 
int contador = 5;
contador++;  // ahora vale 6
contador--;  // vuelve a 5
System.out.println(contador);

++ suma uno y -- resta uno. Los verás muchísimo cuando lleguemos a los ciclos.

04Cambiar de tipo

🔄Conversión de tipos (casting)

Convertir tipos es como pasar agua entre vasos de distinto tamaño. De un vaso chico a uno grande no se derrama nada; al revés, sí — y por eso Java te pide permiso.

Chico → grande: automático. Grande → chico: hay que forzarlo y se pierden decimales.
?
Al pasar un int a double, ¿se pierde información? ¿Y al pasar un double a int?
RespuestaDe int a double (chico a grande) no se pierde nada: Java lo hace automáticamente (conversión implícita o widening). De double a int (grande a chico) sí se pierden los decimales, así que Java te obliga a forzarlo con un cast explícito y te advierte del riesgo (conversión explícita o narrowing).

Antes del código: mostramos las dos direcciones. La implícita ocurre sola; la explícita necesita el (int) delante.

Conversiones.java 
public class Conversiones {
    public static void main(String[] args) {
        int enteros = 5;
        double aDecimal = enteros;   // implícita: se convierte solo
        System.out.println(aDecimal); // 5.0

        double precio = 9.99;
        int precioRedondeado = (int) precio;  // explícita: el (int) es el casting
        System.out.println(precioRedondeado); // 9  (corta, NO redondea)
    }
}
?
¿(int) 9.99 da 10 o 9?
RespuestaDa 9. El casting corta los decimales, igual que la división entera — no redondea. Si quisieras redondear de verdad, usarías Math.round(), que veremos más adelante.
⚠️
Si escribes int x = precio; sin el (int), Java no compila: avisa que la conversión puede perder información. Ponerle (int) es tu forma de decirle "sí, lo sé, hazlo".
05Comparar valores

⚖️Operadores relacionales

Hasta ahora calculábamos. Ahora comparamos. Y comparar siempre da una de dos respuestas: verdadero o falso — es decir, un boolean.

OperadorSignificado
==¿es igual a?
!=¿es distinto de?
>¿mayor que?
<¿menor que?
>=¿mayor o igual?
<=¿menor o igual?

Antes del código: comparamos una edad contra 18 y guardamos el resultado de la comparación en una variable boolean.

Comparaciones.java 
public class Comparaciones {
    public static void main(String[] args) {
        int edad = 20;

        System.out.println(edad >= 18); // true
        System.out.println(edad == 18); // false
        System.out.println(edad != 18); // true

        boolean esMayorDeEdad = edad >= 18;
        System.out.println("¿Es mayor de edad? " + esMayorDeEdad);
    }
}

El resultado de una comparación se puede guardar en una variable boolean. Esto será clave para los condicionales de la próxima clase.

El error más famoso: = vs ==
?
¿Cuál es la diferencia entre = y == ?
Respuesta= (uno solo) asigna: "guarda esto aquí". == (doble) compara: "¿son iguales?". Para comparar siempre se usa ==. En Java, escribir if (edad = 18) ni siquiera compila, porque if espera un boolean y una asignación da un número — Java te protege de ese error clásico.
⚠️
Ojo con los textos: == no se usa para comparar dos String de la forma intuitiva — para texto se usa .equals(). Lo veremos bien más adelante; por ahora, == lo usamos con números y booleanos.
06Combinar condiciones

🔗Operadores lógicos

A veces una sola comparación no basta: "para entrar tienes que ser mayor de edad Y tener cédula". Eso es lógica: combinar varias condiciones en una sola respuesta.

OperadorNombreDa true cuando…
&&Y (AND)ambas condiciones son verdaderas
||O (OR)al menos una es verdadera
!NO (NOT)invierte: true→false, false→true

Antes del código: combinamos condiciones con AND, OR y NOT sobre datos de un cliente.

Logica.java 
public class Logica {
    public static void main(String[] args) {
        int edad = 20;
        boolean tieneCedula = true;

        System.out.println(edad >= 18 && tieneCedula); // true (las dos se cumplen)

        boolean esFinDeSemana = false;
        boolean esFestivo = true;
        System.out.println(esFinDeSemana || esFestivo); // true (con una basta)

        System.out.println(!tieneCedula); // false (invierte)
    }
}
?
¿Cuánto dan: true && false, true || false, y !false ?
Respuestatrue && false → false (el AND exige que las dos sean verdaderas). true || false → true (al OR le basta con una). !false → true (el NOT invierte el valor).
Dato profesional: el cortocircuito

&& y || evalúan de izquierda a derecha y se detienen apenas saben la respuesta. En A && B, si A ya es false, Java ni mira B. En A || B, si A ya es true, ni mira B.

📚
Dato: && y || son operadores de evaluación en cortocircuito: el operando derecho solo se evalúa si el izquierdo no determina ya el resultado.
💡
¿Por qué importa? Evita errores y mejora el rendimiento. Lo agradecerás al validar datos: "si el dato existe Y es válido" — primero verificas que exista, y solo entonces miras si es válido.
07Programa interactivo

⌨️Scanner: leer datos del usuario

Hasta ahora poníamos los datos a mano. Un programa de verdad le pregunta al usuario. Para leer desde la consola usamos Scanner.

Antes del código: importamos Scanner, lo creamos, pedimos la cuenta y el número de personas, y dividimos el total. Estas son las cinco partes de todo programa con Scanner.

RestauranteInteractivo.java 
import java.util.Scanner;   // 1. importar, va arriba del todo

public class RestauranteInteractivo {
    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);  // 2. crear el lector

        System.out.print("¿Cuánto fue la cuenta? ");
        double cuenta = sc.nextDouble();       // 3. leer un decimal

        System.out.print("¿Cuántas personas? ");
        int personas = sc.nextInt();           // 4. leer un entero

        double propina = cuenta * 0.10;
        double total = cuenta + propina;
        double porPersona = total / personas;

        System.out.println("Total con propina: " + total);
        System.out.println("Cada persona paga: " + porPersona);

        sc.close();   // 5. cerrar el lector
    }
}
1
Importar

import java.util.Scanner; trae la herramienta. Va arriba, antes de public class.

2
Crear el lector

new Scanner(System.in) lo conecta al teclado.

3
Leer decimal

nextDouble() lee un número con decimales.

4
Leer entero

nextInt() lee un número entero.

5
Cerrar

sc.close() cierra el lector al terminar.

⚠️
Punto o coma en los decimales: según la configuración regional del computador, nextDouble() puede esperar la coma (80,5) en vez del punto (80.5). Si te da error al escribir un decimal, prueba con coma.
El bug clásico del Scanner (el momento de oro)
?
Si lees un número con nextInt() y luego un texto con nextLine(), el programa "se salta" el texto y no te deja escribirlo. ¿Por qué?
RespuestaCuando escribes un número y presionas Enter, el teclado envía el número y un salto de línea invisible (\n). nextInt() toma el número pero deja el salto de línea ahí tirado. Cuando llega nextLine(), encuentra ese salto sobrante, lo toma como si fuera tu respuesta (vacía) y sigue de largo. No es un error tuyo: es un comportamiento conocido del Scanner.

Antes del código: la solución es de una línea — un sc.nextLine() extra que "se come" el salto de línea sobrante antes de leer el texto.

RestauranteInteractivo.java 
int personas = sc.nextInt();
sc.nextLine();   // ← consume el salto de línea pendiente

System.out.print("Nombre de quien paga: ");
String nombre = sc.nextLine();   // ahora SÍ espera tu respuesta
System.out.println("Gracias, " + nombre);
📚
Regla mental: después de leer un número con nextInt() / nextDouble(), si lo siguiente es un nextLine(), pon un sc.nextLine() de limpieza en medio. Es un comportamiento documentado del Scanner en el rastreador oficial de Java (JDK-8350190).
08Junta todo · con Cursor AI

🤖Validador de cuenta de restaurante

Juntamos todo lo de hoy en un solo programa, construido con ayuda de Cursor AI como copiloto. La regla: la IA te ayuda a escribir, pero tú entiendes cada línea.

El reto
1
Pedir datos

Cuenta (decimal), número de personas (entero) y si es cliente frecuente (nextBoolean()).

2
Calcular

Propina (10%) y total.

3
Aplicar lógica

Si es cliente frecuente Y la cuenta supera 100.000 → 5% de descuento sobre el total.

4
Repartir

Dividir el total final entre las personas y mostrar todo con mensajes claros.

💡
Cómo usar Cursor AI bien: nota la diferencia entre "hazme el ejercicio" y un prompt donde tú dices qué sabes y qué límites pones ("ya sé Scanner, operadores y casting; no uses temas que no he visto como ciclos o métodos; deja comentarios explicando cada bloque"). El segundo te hace mejor desarrolladora; el primero te hace dependiente. Revisa siempre lo que propone, línea por línea — la IA es brillante y también se equivoca.

Antes del código: el programa pide los datos, calcula propina y total, aplica el descuento solo si se cumplen las dos condiciones, y reparte entre las personas.

ValidadorRestaurante.java 
import java.util.Scanner;

public class ValidadorRestaurante {
    public static void main(String[] args) {
        final double PORCENTAJE_PROPINA = 0.10;
        final double DESCUENTO_FRECUENTE = 0.05;
        final double TOPE_DESCUENTO = 100000;

        Scanner sc = new Scanner(System.in);

        System.out.print("Valor de la cuenta: ");
        double cuenta = sc.nextDouble();

        System.out.print("Numero de personas: ");
        int personas = sc.nextInt();

        System.out.print("¿Cliente frecuente? (true/false): ");
        boolean frecuente = sc.nextBoolean();

        double propina = cuenta * PORCENTAJE_PROPINA;
        double total = cuenta + propina;

        if (frecuente && cuenta > TOPE_DESCUENTO) {
            total = total - (total * DESCUENTO_FRECUENTE);
        }

        double porPersona = total / personas;

        System.out.println("Propina: " + propina);
        System.out.println("Total final: " + total);
        System.out.println("Cada persona paga: " + porPersona);

        sc.close();
    }
}

Ese if es una probadita de lo que viene: condicionales. No te preocupes por su sintaxis todavía — la lógica frecuente && cuenta > TOPE ya la entiendes de los bloques de comparación y lógica.
